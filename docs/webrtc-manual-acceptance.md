# DropVoice WebRTC 扫码直连 — 人工验收操作手册

> 本手册指导你按真实用户场景二次验收 WebRTC 扫码直连功能。
> 自动化验收报告见 `docs/webrtc-acceptance-report.md`。

---

## 前置准备

### 1. 启动信令服务器（pairing-server）
```bash
cargo run --manifest-path apps/pairing-server/Cargo.toml
# 监听 127.0.0.1:38424
```

### 2. 启动桌面应用
```bash
pnpm dev:tauri
# 桌面窗口打开，自动 start_server（生成配对码 + heartbeat 注册）
```

### 3. 启动手机 PWA（dev）
```bash
pnpm dev:mobile
# 手机浏览器访问 http://<开发机IP>:5174
```
> 生产验证：PWA 部署到 `https://dropvoice.bytehome.fun`，桌面/手机同局域网。

## 验收场景

### 场景 1：首次配对（扫码直连）— 核心流程

**预期**：手机扫码 → <2s 自动连上 → 设备列表出现桌面 → 打字即注入。

**步骤**：
1. 桌面窗口显示二维码（`dropvoice://pair?code=XXXXXX&device=...&name=...`）+ 6 位配对码
2. 手机 PWA 点击「添加设备」→「扫码连接」
3. 手机摄像头扫描桌面二维码
4. **预期**：手机设备列表出现桌面名（如 "My PC"），状态「已连接」
5. 手机输入框打字「你好世界」→ 点发送
6. **预期**：桌面焦点窗口自动注入「你好世界」

**通过标准**：
- [ ] 二维码格式为 `dropvoice://pair?...`（非旧的 `http://IP:port`）
- [ ] 扫码后无需手动输入配对码（QR 载荷已含 code，自动连接）
- [ ] 连接耗时 <2s
- [ ] 文本正确注入桌面光标位置

---

### 场景 2：配对码过期 / 错误

**预期**：配对码 5min 过期后，重连需重新扫码。

**步骤**：
1. 桌面显示配对码 A
2. 等 5 分钟（配对码 TTL 过期）
3. 手机用旧码 A 的 QR 尝试连接

**预期**：
- [ ] 连接失败，桌面日志显示 `credential invalid`（code 过期）
- [ ] 手机提示「配对码无效或已过期」
- [ ] 桌面重新生成新配对码 B，QR 更新

---

### 场景 3：重连（token 自动）

**预期**：手机切后台再回来，自动用 token 重连，无需扫码。

**步骤**：
1. 完成场景 1（首次配对成功，token 已持久化）
2. 手机切到其他 App（PWA 后台，连接断开）
3. 切回 PWA

**预期**：
- [ ] visibilitychange 触发自动重连（约 2s）
- [ ] 设备状态恢复「已连接」
- [ ] 重连不签发新 token（沿用持久化的旧 token）

---

### 场景 4：多设备添加 + 切换发送目标

**预期**：手机可添加多台桌面，切换发送目标。

**步骤**：
1. 手机已连接桌面 A
2. 点击「添加设备」→ 扫桌面 B 的二维码
3. **预期**：设备列表出现 A + B，均「已连接」
4. 切换发送模式：「全部」群发 / 单选某台

**通过标准**：
- [ ] 设备列表显示 A 和 B
- [ ] 群发：两台桌面都收到文本
- [ ] 单选 A：仅 A 收到

---

### 场景 5：桌面隐藏到托盘（后台注入）

**预期**：桌面隐藏到托盘后，手机继续打字仍注入成功。

**步骤**：
1. 桌面点关闭按钮 → 隐藏到托盘
2. 手机继续打字

**预期**：
- [ ] 桌面隐藏后手机仍能发送
- [ ] 文本正确注入（Tauri 2 隐藏窗口不节流，已实验验证）
- [ ] 托盘图标双击恢复窗口

---

### 场景 6：AP 隔离网络（边界场景）

**预期**：AP 隔离下无法连接，提示明确错误。

**步骤**：
1. 连接公共 Wi-Fi（咖啡馆/酒店，通常开 AP 隔离）
2. 尝试配对

**预期**：
- [ ] 连接超时（ICE failed）
- [ ] 手机提示「请检查是否在同一局域网 / AP 隔离设置」

---

### 场景 7：信令服务器离线 / SSE 未就绪

**预期**：桌面刚启动时 SSE 未就绪，手机首次连接超时。

**步骤**：
1. 桌面启动瞬间（heartbeat 注册 → SSE 建立有短暂窗口）
2. 立即扫码连接

**预期**：
- [ ] 手机长轮询 30s 超时（204）
- [ ] 提示「连接超时，请重试」
- [ ] 桌面 SSE 就绪后重试成功

## 异常排查

| 现象 | 排查 |
| --- | --- |
| 扫码无反应 | 确认 PWA 在 HTTPS / localhost（`isSecureContext`）；检查 `parseQrPayload` 返回非 null |
| 连接超时 | 桌面日志查 SSE 是否建立（`pairing_token` emit）；信令服务器是否运行 |
| 文本不注入 | 桌面焦点窗口是否可输入；`inject_text` 命令是否注册；ConnectionManager 队列 |
| 配对码不显示 | `get_connection_info` 返回 `pairing_code`；`issue_pairing_code` 是否调用 |
| token 驱逐 | 连接令牌达 100 上限 FIFO 驱逐 → 桌面发 `{type:"error",code:"token_evicted"}` → 手机需重新扫码 |
